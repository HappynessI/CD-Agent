# 实验 5c：补全方式的变体与端到端估计

代码：`probe/exp5c_prepare.py`（候选与切块的直接并入，含 oracle 和检测器概率规则）、`probe/exp4c_sam3.py --base exp5c`（切块的 SAM3 框提示）、`probe/exp4c_compose.py --base exp5c`（计分）。产物在 `exp5c/<数据集>/`。

## 设置

- **候选**：B + G0.05，两个数据集都做。SECOND 另加一组 B + G0.05 + H1，因为 5a 中 H1 覆盖率高于 B；SYSU 上 H1 不比 B 好，不加。候选掩码按 5b 的方式精确重建。
- **切细**：面积大于 4 倍目标中位面积的候选（SECOND 1192 px，SYSU 3888 px；中位面积为全部无信号漏检目标的中位数）切细。
  - 切法：在两期影像叠成的 6 通道图上做 SLIC 超像素，`n_segments` = 图像面积 / 目标中位面积，`compactness` = 10。每个大候选与每个超像素求交，得到切块，面积 < 10 px 的丢弃。
  - 理由：超像素贴合影像边界、与类别无关、计算便宜。三种可选切法中，“与检测器概率 > 0.05 求交”对 G0.05 候选没有作用（它本身就是这样定义的），“SAM3 自动实例”在 5a 中已看到提议数量不足。
- **oracle 确认**：只保留真值占比 ≥ 50% 的候选（不切细时），或真值占比 ≥ 50% 的切块（切细时）。
- **补全方式**：
  - 直接并入：确认后的区域原样并入检测器 0.5 掩码。
  - SAM3 框提示：同实验 4c，两期都跑，取 SAM3 自评分高者。切细后的 SAM3 框提示有约 17 万个切块（SECOND），按 GPU 配额要跑数小时，所以只在**每 5 张取 1 张的确定性子集**（按文件名排序）上做，并在同一子集上重算“直接并入”作对照。
- **不靠真值的端到端**：5b 中最好的单一信号是检测器概率与原尺寸复检，两者在 SECOND 上的 AUC 为 0.787 和 0.798，置信区间几乎重合。这里用检测器区域平均概率，因为对全部约 16 万个候选做复检要额外花一个多小时 GPU，而预期收益在误差范围内。
  - 阈值取 4b 样本上召回 0.8 / 0.6 / 0.4 / 0.2 处的概率值。4b 的规则分数阈值 0.5–0.9 在 4c 中已经全部为负，这里改为按召回扫描，覆盖从宽到严的区间。
  - 两种粒度：候选级确认后直接并入；或先切细，再对每个切块按它自己的平均概率确认后直接并入。
- **指标**：像素级 F1、P、R、ΔF1、新增 TP / FP 像素；对照实验 2 的上界（SECOND +7.81，SYSU +1.89）和 4c 的结果。

## 结论

1. **补全方式是 4c 低估“找”的主要原因。**
   - oracle 确认下，把“候选框提示 SAM3”换成“直接并入候选区域”，SECOND 从 +1.46 升到 +3.05；再把大候选用超像素切细，升到 **+6.96（上界的 89%）**；加上 H1 后为 +8.50。
   - 在同一子集上，切细后用 SAM3 框提示（+5.46 / +2.39）仍不如直接并入（+7.02 / +3.14）：SAM3 在小切块上会向外扩张。
   - 5c 的 oracle 超过实验 2 的 2b 上界（SECOND 109%，SYSU 157%），原因是这里的候选也补到了部分命中目标缺失的像素，而 2b 只补整目标漏检。
2. **需要注意，切块级 oracle 是比实验 2 更宽松的上界。** 切块大小接近目标中位面积，在切块上用真值挑选，接近于“按真值逐块涂色”。所以 +6.96 说明候选的覆盖面加上切细的粒度已经足够，但对确认器的要求也同步变高：它要能在十万级切块的粒度上判对。
3. **不用真值，所有设定都是负的 ΔF1。**
   - 切块级确认比候选级好得多（SECOND 最好 −0.73，候选级 −4.63；SYSU −0.19 对 −0.81）。阈值越严越接近 0，但始终没有转正。
   - 在最严的阈值上，新增 FP 仍是 TP 的 1.8–2.3 倍，补进来的大多是伪变化。
4. **加 H1 提高了 oracle 上界**（+6.96 → +8.50），但没有改善不用真值的结果（−0.73 → −0.74）：H1 带来的新候选同样需要可靠的确认。
