三种做法：固定路线、规则与 Agent

九个典型回放

固定路线：程序写死的工具链，不用任何多模态大模型。同样的原子工具，按固定顺序、固定参数调用。参数原则上在开发集上选，历史选择偏差见下。

规则：固定路线的候选 + 验证器。把候选拆成 8 连通组件，每个组件问一次和 Agent 同一个验证器（同样的裁图和问法），答 no 就删，答 yes 就留。没有规划器，不会补漏，只会删。

Agent：同样的工具和验证器，由规划器自己决定调哪些工具、问哪些组件、答案采不采纳、何时提交；固定核验阶段仍会自动核验提交候选。

三者共享同一套工具；规则和 Agent 共享同一个验证器，固定路线不调用验证器。差别在谁做决定。规则是 Agent 不做任何判断时的下限参照，并非数学性能下界；固定路线衡量不用 MLLM 能到多少。

只换决策者

蓝色是同一套工具，黄色是同一验证器，绿色边框是规划器。规则的答案只用于程序删留；Agent 可补漏、修改和重新选择。在线与离线是独立请求，不保证逐次回答相同。

解释分数时的限制

全量 Agent 分数来自 3 次运行的合并 F1，区间在 README 指定章节；不把单图示例当整集分数，也不把三次整集 F1 的均值与逐会话 F1 中位数混用。T4.1 的 Agent 仅10张单次试跑；T3.2–3.4、T5.4 没有 Agent 全量。没有跑新实验。
