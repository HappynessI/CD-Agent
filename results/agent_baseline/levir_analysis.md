# LEVIR-CD 分析：什么在限制 Agent 的 F1

只用验证集 64 对。数据来自 `code/agent_baseline/levir_analysis.py`。理想决策用了真值，只用来算上限，不进入 Agent 的任何输入。

## 结论

1. 单次运行不足以下结论。两次单跑的 T5.1 相差 2.66 分，之后所有比较都用 3 次重复。
2. 决策还有空间。只做整连通域删除，理想决策能到 87.86，当前 83.27，只拿到约 20%。
3. Agent 的删除有效但不准：整块误检减少的同时，整块漏检增加。核实信号需要更好。
4. 54% 的误检在与真值相连的连通域里，Agent 基本没碰。按连通域决策够不到这部分。
5. 现在不要指望后处理：腐蚀 1 像素 +0.43，开运算几乎不变，3 次投票只比均值高 0.07（T5.1）。

## 上限（从固定路线 I-M-C(SAM3) 出发，F1^c）

| 掩码 | F1^c | P | R |
|---|---:|---:|---:|
| 固定路线 | 82.14 | 74.36 | 91.73 |
| 腐蚀 1 像素 | 82.57 | 78.54 | 87.05 |
| 开运算半径 3 | 82.25 | 74.75 | 91.41 |
| 理想删除（连通域与真值重叠 < 50% 就删） | **87.86** | 84.90 | 91.04 |
| 理想删除 + 理想添加（门限 0.1 的 SAM3 实例，与真值重叠 ≥ 50% 就加） | 87.41 | 80.60 | 95.47 |

理想添加反而略低，因为 50% 的添加标准会带入外溢。这说明只靠现有实例补漏价值有限，也和「最终增加像素的修改多数变差」的观察一致。
