## 待验证问题一：GT-direct teacher-only 工具能力上限

### 要回答的问题

> 从真实 SAM3 初始状态开始，如果离线 GT teacher 能直接产生足够合理的点和框，真实
> SimpleClick/SAM3 能否通过连续执行逐步逼近 GT？

0803 oracle 不是这个能力上限。它先由 production Environment 从当前预测 mask 生成少量固定 region、seed
和 padded box，再让 GT 对其中 shortlist 候选排序。GT 不能创造新坐标、新框或新 Proposal。因此
`no_beneficial` 只说明冻结 Proposal/geometry/shortlist/工具/gate/greedy/max_steps 组合内没有可接受动作，
不等于工具在理想点框下无能力。

### teacher-only 边界

- GT 只允许在离线 teacher 中生成或选择点框，并用于离线评分。
- 必须区分“原始标签”和“由标签算出的坐标”：原始 GT mask/标签路径不得传给 SAM3、SimpleClick、Qwen、
  production Proposal 或 hard gate；但本实验要测试理想点框的工具上限，所以 **GT 派生的 point/box 会作为
  teacher Proposal 进入 Environment，并最终进入真实工具输入**。这正是 teacher-only 上限实验与可部署推理的
  差别，不能写成“GT 完全没有进入工具”。
- Environment evidence 会保存完整 teacher Proposal，包括 error kind、component hash 等 GT 派生审计元数据；
  Executor 与 execution receipt 会看到 point/box、Proposal ROI、component area，以及编码了 error kind/rank/
  padding/action/view 的 teacher region ID。真正的 SAM3 后端只收到 RGB/query/box，SimpleClick 后端收到
  RGB、GT 派生 point 和由 Proposal ROI 限定的当前 mask 上下文。两种后端都不收到原始 GT mask 或标签路径，
  Qwen 完全不调用。该三层边界会写进 artifact，不能把“后端未收到原始 GT”误写成“运行时完全没有 GT
  派生信息”。
- 仍从 fresh production SAM3 T1/T2 building masks 开始。
- 每步只执行一个真实动作；accepted state 连续传递并重新计算 change mask。
- 每步记录 action、geometry、tool receipt、source/next state hashes、hard/RGB gate 和 change 指标；只有数据集
  提供单时相 GT 时，才记录 T1/T2 building 指标。
- 先保持正式 `max_steps=3`；若轨迹持续改善但只因步数耗尽失败，再单独预注册更大步数实验。
- teacher-only artifact 必须显式写 `training_authorized=false`，不得直接作为正式 T-TRAJ/C-ISO 或启动 SFT。
- Qwen 调用保持 0；本门只测工具上限，不测模型策略。

### 0804 GT-direct pilot 预注册

本轮只复测 0803 的 4 个非平凡失败样本：
`train_407_r3c2`、`train_364_r0c2`、`val_43_r1c1`、`val_41_r3c2`。每个样本的 fresh SAM3
初始 T1/T2/change mask 哈希均绑定到 0803 正式 artifact；只要初始化漂移，整条 episode 即判为证据失败，
不能拿不同初态做对比。

每一步以当前 change mask 和 GT 计算：

```text
FN = GT_change AND NOT current_change
FP = current_change AND NOT GT_change
```

teacher 对 FN/FP 做 8 连通域分析，在误差块内部选离边界最远的 point，并构造多 padding box。由于 LEVIR-CD
没有 T1/T2 building GT，teacher 不假装知道唯一正确的时相，而是枚举合法的 T1/T2 路线；SimpleClick 在黑白
seed 都可执行 positive point（增加或细化），白 seed 还可执行 negative point，SAM3 执行 box。每次真实执行后
才用离线 GT 评分，选择严格降低 pixel error 的最佳动作；canonical
Environment 再执行一次所选动作，只有 branch/replay mask 哈希一致才传递到下一步。T1/T2 更新后的 change
mask 由与 0803 相同的 production `MaskPairProcessor` 重建：`overlap_presence`、overlap threshold `0.25`、
两个最小面积阈值均为 `0`；它不是简单的逐像素 XOR。每步一个动作，正式 `max_steps=3`，不调用 Qwen。

为把瓶颈拆开，4 个 track 按失败时才升级的顺序运行：

1. `matched_safe`：最多 4 个 GT-direct 候选，保留 production hard gate 与冻结 RGB gate；
2. `wide_safe`：扩大到最多 4 个误差块、4 种 box padding、每步最多 96 个候选，完整覆盖本轮声明的
   `4 components × 4 paddings × 最多 6 条合法点/框路线`，仍保留两类 gate；
3. `wide_hard`：保持 wide geometry 和 hard gate，只关闭 RGB gate；
4. `wide_raw`：保持真实工具与严格指标改善，但关闭 hard/RGB gate。

所有 track 都从相同 fresh 初态独立开始，最多 3 步。endpoint 与 0803 相同：非空 GT 要求
`IoU >= 0.90` 且 `F1 >= 18/19`；空 GT 要求残余 FP 不超过 64 像素。详细候选序、预算、哈希和判定规则以
`configs/qwen3vl_gt_direct_teacher_0804.json` 为唯一机器可读合同。

结果解释预先冻结如下：

- production 失败而 `matched_safe` 或 `wide_safe` 到 endpoint：已经证明 production Proposal/geometry/候选覆盖
  是该样本的一个实际瓶颈；不能声称它是唯一瓶颈。
- 只有 `wide_hard` 成功：主要新增证据指向 RGB routing/gate。
- 只有 `wide_raw` 成功：工具能改善，但 production hard gate 阻断。
- `wide_raw` 仍失败：只说明“当前真实工具 + frozen MaskPairProcessor composition + 本轮有限 GT geometry +
  greedy 严格改善策略 + 3 步”没有找到终点；不能把该样本只归因给 Proposal，也不能单独归因于工具原语，
  更不能外推为所有交互工具或更长轨迹永远不可达。
- 不同样本落在不同层：最终结论必须写 `mixed bottlenecks`，不能强行二选一。

本 pilot 非盲、只有 4 个样本，回答的是 0803 失败机制，不提供总体泛化率。所有 artifact 都固定
`teacher_only=true`、`qwen_invoked=false`、`training_authorized=false`，不产出正式 C-ISO/T-TRAJ。

### 效率解释：1776 个候选不是正常 Agent 推理开销

这次 teacher-only runner 为了测上限而做真实工具穷举。wide geometry 每一步的理论候选上限是：

```text
最多 4 个 FN/FP 误差连通块
× 4 种 box padding（0、0.1、0.25、0.5）
× 最多 6 条合法路线
= 每步最多 96 个候选
```

最多 6 条路线来自 T1/T2 上的两个 SAM3 box、两个 SimpleClick positive point，以及 seed 为前景时最多两个
SimpleClick negative point。实验又从相同 fresh 初态独立运行 `wide_safe`、`wide_hard`、`wide_raw` 三条
gate counterfactual track；另有每步最多 4 个候选的 `matched_safe`。因此每个样本 3 步的理论上限是
`3 × (4 + 3 × 96) = 876` 个候选，三个样本理论上限为 2628；实际因路线缺失或 track 提前停止而执行 1776 个。

这里的“候选”不是只生成坐标。每个候选都会创建隔离分支，调用真实 SAM3 或 SimpleClick 得到 mask，再由离线
GT 评分；30 个被选动作还各有一次 canonical replay。因此三个完整样本实际约有
`1776 + 30 = 1806` 次编辑工具调用，尚未计入 fresh SAM3 初始化、artifact 写入和哈希检查。四条 track 彼此
独立，不能把 30 个选择动作理解成一条 30 步轨迹。

本次时间账如下：

- 三个完整 shard 的单卡 GPU 时间合计 `12:17:43`；因实际只部分并行，从首个正式 shard 启动到第三个完成，
  墙钟时间为 `07:32:51`。
- 从 0803 证据恢复开始算到第三个完成约 `07:40:32`；算到第四个取消并由 validator 完成 fail-closed 收尾约
  `07:46:49`。
- 被取消的第四个 shard 仍额外占用约 `02:53:42` 单卡 GPU；正式 pilot array 实际累计约 `15:11:25`
  GPU 时间。1-GPU smoke 另占 `00:01:32`。

正常 Agent 不执行这套 GT 穷举。production runner 每轮只调用一次 `agent.act()`，再执行一个
`environment.step()`；若 `max_steps=3`，每个样本至多执行 3 个编辑动作，三个样本至多 9 个，而不是 1806 个
候选/回放工具调用。正常路径还会有 fresh SAM3 初始化、Qwen/Verifier 推理和安全检查，但工具调用数量不会自然
膨胀到本实验规模。只有显式把 oracle search、self-consistency 或多候选真实 reranking 带入推理时，才会再次
出现这种开销；因此不能用本次 7 小时以上的 teacher runtime 推断正常 Qwen Agent 的线上延迟。

若以后继续上限实验，可在新预注册下按以下顺序降本，不能事后改变本轮证据：

1. 只回答工具上限时先跑 `wide_raw`；本次三个样本的 raw 候选为 `628/1776`，约占 35%，可避免重复完整
   track ladder。若要比较 gate 或形成安全轨迹，仍需补跑对应 safe track。
2. 按 `source state hash + action geometry + tool` 缓存确定性结果；不同 track 在分叉前复用同一真实执行，
   选中动作仍做 canonical replay。
3. 批处理同一图像上的 SAM3 多框/SimpleClick 多点，并复用图像 embedding 与常驻模型进程。
4. 先用不执行工具的廉价 Proposal/ranker 缩到 top-k，再做真实调用；这会改变上限搜索覆盖，必须单独预注册。

### 留存轨迹的训练数据价值

这些 artifact 应继续 append-only 保留，但当前不能直接作为正式 Qwen SFT 数据：

| 用途 | 当前价值与限制 |
| --- | --- |
| 工具、Proposal、gate 和失败轨迹分析 | 高；每步真实 mask、指标、gate、receipt 和 replay 均已记录 |
| 候选排序器或 value/ranker 监督 | 有潜力；1776 个候选比只保留30个 winner 包含更多正负与改进幅度信息 |
| 单步局部改善 C-ISO 种子 | 少量有潜力；仅限安全、严格改善、回放一致且能由 GT-free 输入表示的动作 |
| 完整 Agent T-TRAJ / 主 SFT | 当前不合格；三个完整样本均未到 endpoint，且第四个缺失 |

不能直接训练的原因：

- teacher 使用 GT 生成 geometry，并在真实执行大量候选后用 GT 选最优；推理时 Qwen 没有 GT，也不能先试完
  所有候选。GT 可以作为离线监督标签，但不得进入模型输入，而且必须证明动作可由推理时信息预测或覆盖。
- 这些只是“持续改善的前缀”，没有教会模型怎样到达目标或何时正确停止。只用它们训练会重现此前指出的风险：
  模型学会局部一步，却没有完整流程能力。
- `wide_hard`/`wide_raw` 包含未通过 RGB 或 hard gate 的动作；尤其不能把由 gate-bypass 状态继续产生的后续
  step 冒充 production-safe trajectory。
- 30 个选择动作来自多条独立 counterfactual track，含重复状态/动作，且只有 3 个非盲样本；动作分布又高度
  偏向 SAM3 box（27 box、3 point），不足以支持泛化训练。

若以后将其转为辅助训练数据，必须先：按 source/action/next-state hash 去重；分开 safe 与 counterfactual；
删除 GT mask、GT error metadata 等模型输入泄漏；把输入重建成线上可见的 RGB、当前 masks、历史和 GT-free
Proposal；通过 Proposal coverage / improvement-regret bridge；按 parent/location 隔离 train/val/test。
只有使用线上可见信息生成候选、通过安全 gate、真实 replay 并最终到达 endpoint 的连续轨迹，才可升级为正式
T-TRAJ；未到 endpoint 的安全前缀最多作为显式标注的 auxiliary improvement data。当前正式 C-ISO/T-TRAJ
仍为 0，`training_authorized=false`。

按用户指示，本次 closeout 完成后暂停；不继续扩展 `max_steps`、不做 Proposal bridge、不构造 C-ISO/T-TRAJ、
不启动 SFT，也不启动其他工具比较。

### 两类 GT 条件必须分开

若数据集提供 T1/T2 building masks：

- `FN_t = GT_t AND NOT Pred_t` 可生成 positive point/box；
- `FP_t = Pred_t AND NOT GT_t` 可生成 negative point；
- 可同时验证 T1 IoU、T2 IoU、最终 change IoU/F1；
- 可发现“两侧都分错但 change mask 错误抵消”的伪改善。

若数据集只有 change mask GT，例如 LEVIR-CD：

- 可以直接针对最终 change error 设计 teacher geometry，并验证 change-mask 上限；
- target view 与动作方向必须使用冻结的 RGB 语义规则，或在 teacher-only 分支中枚举所有合法路线并完整报告；
- 不能唯一推出应该修改 T1 还是 T2，也不能证明单时相 building mask 被语义正确恢复；
- 该结果必须标为 change-only teacher upper bound，不能冒充 T1/T2 building recovery。

### 结果如何解释

- 在相同样本、初始状态、真实工具、组合规则、gate、候选预算和步数下，仅替换 geometry 来源后，若
  GT-direct 成功而 production Proposal 失败，可证明 Proposal/geometry/候选覆盖是**至少一个**瓶颈，
  下一步做 GT-free Proposal bridge；不能直接声称 Proposal 是唯一瓶颈。
- GT-direct 也失败：优先检查工具原语、组合规则、gate、greedy 策略和步数；不能先训练 Qwen。
- 只有 production 可见信息生成的动作能覆盖 teacher 动作，并经真实 replay 达到终点，才有资格进入正式
  T-TRAJ/C-ISO 构造。

### Proposal bridge 验证

teacher upper bound 之后必须测训练/推理 gap：

1. production Proposal 是否覆盖 teacher 的有效区域、点或框；
2. GT-free 候选中最佳动作相对 teacher 最佳动作损失多少改善量；
3. 是否可通过多 seed、多尺度 box、多 padding、边界/不确定区域、自动 mask proposal 提高覆盖；
4. 候选 geometry 必须由 RGB、当前 masks 和历史生成，不能使用 GT；
5. GT 只负责离线标注或排序这些可部署候选。

GT-direct 轨迹可用于上限分析和监督 GT-free proposer/ranker，但在 Proposal bridge 通过前，不得把任意
GT 坐标轨迹直接当作线上可复现的 golden trajectory。

## 待验证问题二：不同工具模型比较（待定）

该问题可能增加接入、权重和 GPU 时间，暂记为 `pending teacher discussion`，不假装已经完成。

最小优先实验是 SAM3 point 与 SimpleClick point 的 paired shadow ablation：使用相同 RGB、初始状态、
point geometry、Proposal ROI、seed 和 gate；SimpleClick 保留 current mask/click history；SAM3 单点产生多个

注意：当前正式 runtime 没有开放 SAM3 point；0803 的 SAM3 动作全部是 box。shadow 实验不能改变现有 Agent
动作协议，也不能让 GT 在 SimpleClick/SAM3 之间替线上策略选择工具。

若需要继续扩展，候选顺序暂定：SAM3 interactive branch、SAM2.1 image predictor、FocalClick；
RSPrompter 更适合遥感 building 初始化或 Proposal，不应直接冒充 point executor。BIT/ChangeFormer 是最终
change detection baseline，不属于 T1/T2 building-mask 修改工具。

## 待验证问题三：数据集选择

### LEVIR-CD 的限制

LEVIR-CD 提供 change mask GT，但不提供逐像素 T1/T2 building mask GT。它足以评测最终 change mask，
不足以唯一判断：

- 应修改 T1 还是 T2；
- 应增加建筑还是删除误分；
- SimpleClick/SAM3 是否真正修好了单时相 building mask；
- change 改善是否来自正确修复，还是两侧错误碰巧抵消。

即使采用理想化关系 `Change = T1_building XOR T2_building`，只知道 Change 也不能唯一反推出两侧
building masks；实际数据集的 change 标注还可能因实例定义、边界和配准而不严格等于逐像素 XOR。

### 候选路线

更合理但仍待验证的路线：

1. 选择同时提供 T1/T2 building masks 的配对遥感数据集，用于 GT-direct teacher upper bound、Proposal
   bridge、轨迹构造、同域 baseline 训练与内部 held-out 验证；
2. 将未参与训练、调参、筛样或早停的 LEVIR-CD parent/location 冻结为外部 change-mask 泛化测试；
3. 分开报告同域单时相 building 指标、同域 change 指标和 LEVIR-CD 跨数据集 change 指标；
4. LEVIR-CD 结果只能支持 change 输出跨域表现，不能支持 T1/T2 building masks 或动作方向正确的结论。

这不是已确定的最佳方案。新数据集入场前必须审计：数据许可、传感器、空间分辨率、时间跨度、地理划分、
配准质量、building 类别定义、mask 身份与 parent hash。还要逐像素检查数据集官方 change GT 是否等于
`T1_building XOR T2_building`；若不一致，必须量化并解释标注定义或配准边缘差异。

若任何 LEVIR-CD 样本参与训练、调参、样本筛选、阈值选择或早停，后续不能称其为纯外部泛化测试，只能称
transfer 或 mixed-data evaluation。0803 六样本和反复查看的 CORE3 也不能承担泛化结论；应重新冻结未查看、
parent/location 隔离的测试 manifest。

## 建议验证顺序与放行门

1. **Dataset gate**：筛选带 T1/T2 building masks 的数据集；完成许可、定义、配准、XOR、一致性、split、
   hash manifest 审计。
2. **Teacher upper-bound gate**：GT-direct geometry、真实工具、连续状态、最多 3 步；同时报告单时相和
   change 指标。全部标为 teacher-only。
3. **Proposal bridge gate**：测 GT-free Proposal 对 teacher 有效动作的覆盖率和 improvement regret；覆盖不足
   先改 Proposal。
4. **Deployable trajectory gate**：只用推理时可见信息生成候选，GT 只排序/打分；真实 replay 到 endpoint 后，
   才产生候选 T-TRAJ，并从同一轨迹机械切出 C-ISO。
5. **Training gate**：数据 schema、lineage、hash、parent split、模型可见格式和授权全部通过后，才设计
   baseline/SFT；teacher-only 数据永不直接获训练授权。
6. **Generalization gate**：配对-mask 数据集内部 held-out 测试，加 untouched LEVIR-CD 外部 change-mask
   测试；两类结果分开管理和报告。

工具横向比较可在第 2 门内做小型 shadow，也可待与老师确认后扩展；它不阻塞先完成 dataset audit 和
GT-direct 协议设计。

## 禁止过度结论

- GT-direct 成功不等于当前 Agent 能在无 GT 推理时找到动作。
- GT-direct 成功不等于 Proposal 是唯一瓶颈。
- GT-direct 失败不等于所有工具或更长步数永远不可达。
- LEVIR-CD change IoU/F1 改善不等于 T1/T2 building masks 都正确。
- 6 个非盲样本不能代表总体泛化。
- oracle 工具可达不等于 Qwen 已学会规划，也不自动授权训练。
