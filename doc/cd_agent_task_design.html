变化检测智能体：能力与任务设置

研究方向是“变化检测 + 变化检测智能体”，开放词汇变化检测是其中一个任务。任务围绕两件事来设：变化检测流程中存在哪些问题，以及 Agent 解决这些问题时需要具备哪些能力。参照师兄的做法：灾害智能体按灾害的四个特点建任务，另一位师兄按增、删、改、查建任务。

灰底的“评审建议”是 Claude 的补充。2026-10-30 起，能力从“读图、判断、定位、工具调度”四项扩为六项，新增“搜索”和“核验”两项能力及对应的任务 1.2 搜索、1.6 核验，Ethan 已确认。

01全流程：变化检测在哪里出问题

步骤 1 · 输入T1 / T2 两期影像可附带类别文本或需求文本
→
步骤 2 · 检测变化检测器输出变化掩码 change mask
→
步骤 3 · 存在的问题
误检：报了变化，其实没变 漏检：真实变化没报出来 掩码边界质量差
引入 Agent 之后理解 → 搜索可疑区域 → 判断是否变化 → 定位区域 → 调度工具修改掩码 → 核验后采纳或回滚误检场景检查变化掩码之内的区域，漏检场景检查变化掩码之外的区域（见 02 节）

02Agent 需要的六种能力

按 Agent 工作的顺序排列。每项能力下面拆出子能力；“原有”是原方案的四项，“新增”是根据 OVCD-v0 补上的两项。卡片下方说明误检、漏检两个场景各用到哪些子能力。

能力 1原有 · 原“读图”

理解

  • 1.1 地物识别：两期影像中各区域是什么类别
  • 1.2 判定标准理解：从类别名、示例或自然语言中归纳“什么算变化、什么不算”
能力 2新增

搜索

  • 2.1 漏检搜索：在检测结果之外提出可疑区域，并排序
  • 2.2 待查排序：在检测结果之内，决定先查哪个区域
误检2.2 掩码之内先查哪个漏检2.1 掩码之外去哪里找
能力 3原有 · 细化

判断

  • 3.1 存在性：区域内有没有目标类别的变化
  • 3.2 取舍：这个区域整体该保留还是删除
  • 3.3 方向与类型：新增、消失或类型转换
误检判断检测结果之内的区域漏检判断检测结果之外的区域
能力 4原有 · 细化

定位

  • 4.1 整目标：给出点或框，让工具分出整个目标
  • 4.2 局部：标出目标外多出的部分
  • 4.3 时相选择：在 T1 还是 T2 上分割
误检4.2 删除多余局部漏检4.1 补回整个目标
能力 5原有 · 细化

工具调度

  • 5.1 选工具：SAM 框提示、SAM3 类别裁剪、分数过滤，或不动
  • 5.2 给提示和参数：点、框、门限
  • 5.3 预算与停止：去误检和补漏各分多少调用，何时停
能力 6新增

核验

  • 6.1 结果核验：工具输出先检查，不对就回滚
  • 6.2 工具可靠性：判断工具在这张图上靠不靠得住
误检场景

检查变化掩码之内的区域：报出来的变化里，哪些不是真变化、哪些部分多出来了。

2.2 待查排序 → 3.2 取舍 → 4.2 删除多余局部 → 5.1 选工具（如 SAM3 类别裁剪） → 6.1 结果核验

漏检场景

检查变化掩码之外的区域：哪些真变化没有报出来。

2.1 漏检搜索 → 3.1 存在性 → 4.1 补回整个目标、4.3 时相选择 → 5.2 给提示 → 6.1 结果核验

误检是 OVCD-v0 中错误的大头：误检像素占全部错误的 68–80%，其中 69–87% 是贴在已检出目标外面的多余像素，所以误检场景更依赖“局部删除”（4.2）和工具，而不只是整块删除。

04OVCD-v0 十一轮带给任务设置的结论

OVCD-v0 在 LEVIR-CD building 上跑了 11 轮，零样本 MLLM 在这个任务上已经做够。下面六条是它对任务设置的结论，第 02 节的六项能力就是据此调整的。详细过程见 doc/ovcd_v0_11rounds.html。

结论 1

初始化越强，MLLM 作用越小

MLLM 核实带来的增益：M-C-I 上 +2.1，I-M-C 上 +1.7，ReA-OVCD 上只有 +0.1。

判断任务应放在初始化弱、数据难的地方，或没有现成初始化的查询上。LEVIR 建筑已经饱和。

结论 2

不调用 MLLM 的工具贡献最大

SAM3 类别裁剪在 I-M-C 上 +6.2，在 ReA-OVCD 上加分数过滤 +1.3。

工具调度是能力体系的中心，动作空间必须包含这些工具。

结论 3

工具要逐图核验

裁剪的开关现在由验证集统一决定。SAM3 漏检的图上，裁剪会删掉真变化。

由此新增能力 6“核验”和任务 1.6。

结论 4

瓶颈常在“去哪里看”

候选池覆盖充足，截断到前 20 个后大部分漏检丢失。

由此新增能力 2“搜索”和任务 1.2。

结论 5

判断能力取决于候选

同一个 Qwen，在不同来源的候选上 AUC 从 0.74 到 0.94 不等。

任务 1.3 要固定候选定义，并分来源报告。

结论 6

每个任务都要有“不用 MLLM”的对照

只在验证集上把 ReA-OVCD 的阈值调到 0.75，测试集 85.94，与完整 Agent 相同。

没有这个对照，会把调阈值的收益算到 Agent 头上。

07第一大类：模块任务

按 Agent 的工作顺序排列：理解 → 搜索 → 判断 → 定位 → 工具调度 → 核验，每项能力对应一个任务。数据都来自第 06 节的数据集 v0 和示例集。

任务 1.1 · 理解

遥感图像理解

待定
设想
给定类别集合，让 MLLM 输出两期对象的类别。
目的
检验 MLLM 能否认出影像里的地物，以及文本对应的类别。

评审建议做成区域级：给一个区域，分别问 T1、T2 的类别。SECOND 的两期语义图可直接当真值，零标注；也可以和 1.3 共用数据。判定标准理解（子能力 1.2）留给端到端任务 2.3–2.6（示例、自然语言两种前置条件）检验。

任务 1.2 · 搜索（新增）

在固定预算内决定先看哪里

基于 v0
设定
在 v0（见任务 1.3）中给定检测结果，分两侧：
误检 给变化掩码之内的连通域排序，最可能是误检的排在前面；
漏检 提出变化掩码之外的可疑区域，并排序。
输出
候选区域列表（掩码或框），按可疑程度排序。
评测
误检侧：前 k 个连通域中误检像素的比例。漏检侧：前 k 个候选覆盖的漏检目标和漏检像素比例。k = 10、20、50。
对照
规则来源：检测器低置信区域、SAM3 两期分割差异、分块 SAM3；按规则分数排序。
目的
单独衡量“去哪里看”，和判断分开。

评审建议OVCD-v0 的数字可作参照：误检侧改为按变化分数排序后，验证集 +1；漏检侧原始候选覆盖 83–95% 的孤立漏检，前 20 个只剩 11–22%；SAM3 改为分块推理后，前 20 个的覆盖从 8.0% 升到 16.6%。真值直接由 GT 计算，零标注。

任务 1.3 · 判断

变化判断：数据集 v0

先做
数据
SECOND 的 building 类，单独抽成一个集合：T1、T2、T1 语义、T2 语义、building 变化掩码。挑 250 张作为初始开发集 v0，之后需要再扩。
标注
检出的真实变化漏检误检三种颜色，以 GT 为准。
审核页
抽几个典型例子，展示全景和近景。
要想清楚
候选怎样构造，才能把想让 MLLM 区分的变化区域分出来：给 MLLM 看的图应该是什么形状、什么大小。
划分
训练集、验证集、测试集。
目的
得到一个能识别变化的判断器。

评审建议初始化建议用 ReA-OVCD（免训练，不受 SECOND 训练集限制）。负样本要包括没变化的建筑。候选分两档：v0-oracle 用 GT 推出的区域，v0-real 用实际能得到的候选，两者的差距本身就是结论。按图像划分，例如 150/50/50。exp6l 中 Qwen3.5-4B 的同类判断 AP 只有 0.071，预期要放低。OVCD-v0 显示同一个 Qwen 在不同候选来源上 AUC 从 0.74 到 0.94 不等，所以要分来源报告；判断标签建议分“存在性”和“取舍”两种（子能力 3.1、3.2）。

任务 1.4 · 定位

给出点或框，让 SAM 分出目标

基于 v0
设定
在 v0 中，已知某个 building 是漏检或误检。
输出
MLLM 输出点或框的坐标，输入给 SAM、SAM3 等工具，把这个 building 分出来。
效果
已知是漏检还是误检，就知道分出来的目标该加上还是删除；加上或删除之后，F1 会变化。
待定
要不要人工确定最佳点或框，作为 golden 数据？还是点只要落在 building 形状内就行？

评审建议不需要人工标。GT 外接框就是 golden 框，用它提示 SAM 的 IoU 是上界。点位影响有多大，可以自动比较中心点、随机内部点和边缘点来实测。评测看三项：命中率、SAM 结果与 GT 的 IoU、F1 变化。SAM 在哪一期上分（新建用 T2，拆除用 T1）也应由 MLLM 决定。除了补回整目标，还要评“删除局部”（子能力 4.2），因为误检里 69–85% 是多出的局部像素。

任务 1.5 · 工具调度

有限预算内取得最大 F1 收益

可能与 1.4 合并
设定
同样已知漏检和误检。
目标
在有限的预算内执行动作，取得最大的 F1 收益。

评审建议每张图最多 k 步，记录每一步后的 F1，画 F1–步数曲线。要注明这是“已知错误类型”的设定；端到端任务里 Agent 并不知道哪里是漏检，两者的数字不能直接比。动作空间要包含不调用 MLLM 的工具（SAM3 类别裁剪、按初始化分数过滤），OVCD-v0 中它们贡献了大部分收益。

任务 1.6 · 核验（新增）

判断工具输出该不该采纳

可先用 OVCD-v0 轨迹
设定
给定两期影像、当前掩码，以及一次工具输出（如 SAM 分割结果、SAM3 裁剪结果）。
输出
采纳或回滚；可选输出：这个工具在本图上是否可靠。
真值
采纳后这张图的 F1 是升还是降，由 GT 自动计算，零标注。
评测
采纳决策的 AUC 与准确率；按决策执行后的 F1，与“总是采纳”“从不采纳”比较。
目的
衡量 Agent 能否发现工具出错，这是它和固定流程的主要区别。

评审建议数据可以先从 OVCD-v0 的轨迹取：11 轮记录了大量工具输出和采纳前后的 F1，正负样本都现成（LEVIR building）。之后在 SECOND 的 v0 上重新生成。典型负例：整图框分出 97 万像素误检；SAM3 在密集小住宅区漏检后的裁剪。

08第二大类：端到端任务 = 前置条件 × 核心变化检测任务

给定类别、给定示例、给定自然语言只是“前置条件”，规定要找什么变化；真正决定输出形式的是中间的核心变化检测任务。核心任务定为两种：二值变化检测和多类别语义变化检测。两者组合得到 6 个端到端任务。

前置条件 ↓ / 核心任务 →C1 二值变化检测输出：符合条件的变化掩码（一张二值图）
指标：F1^c、IoU^c、P、R		C2 多类别语义变化检测输出：变化区域内 T1、T2 各是什么类别
指标：mIoU、SeK、F_scd（SECOND 标准）
P1 给定类别一个类别名或类别集合2.1 例：building → 建筑的变化掩码。即 OVCD，沿用 DynamicEarth 协议，可直接和已有论文比。2.2 例：给定 SECOND 六类 → 每个变化像素的前后类别。
P2 给定示例几对已标好的变化示例2.3 例：给几对“新建厂房”的示例 → 找出同类变化。2.4 例：示例中带有前后类别 → 按示例的类别体系输出前后类别。
P3 给定自然语言一段要求2.5 例：“找出新建的建筑，不包括拆除” → 二值掩码。2.6 例：“标出所有从植被变成建筑的区域” → 带前后类别的结果。

评审建议SECOND 同时有二值变化和两期语义图，一份数据就能支撑两种核心任务。C2 的初始化需要额外设计：ReA-OVCD 只输出单类变化掩码，可以逐类运行，再按两期的类别得分给出前后类别。示例和自然语言两种前置条件里，“判定标准理解”（子能力 1.2）是关键。已有工作中最接近 2.5 的是 RCD、QSCP、DVL-Bench；2.3、2.4 在检索范围内没有找到已有方法。

时间序列变化检测暂不加入。以后加入时，需要设计成公平的任务：同一序列、同一时相数，与双时相方法的输入信息量可比。
