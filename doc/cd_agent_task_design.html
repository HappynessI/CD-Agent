变化检测智能体：能力与任务设置

研究方向是“变化检测 + 变化检测智能体”，开放词汇变化检测是其中一个任务。任务围绕两件事来设：变化检测流程中存在哪些问题，以及 Agent 解决这些问题时需要具备哪些能力。参照师兄的做法：灾害智能体按灾害的四个特点建任务，另一位师兄按增、删、改、查建任务。

灰底的“评审建议”是 Claude 的补充。2026-10-30 起，能力从“读图、判断、定位、工具调度”四项扩为六项，新增“搜索”和“核验”两项能力，Ethan 已确认。2026-11-02 起，搜索不再单独设任务：它和判断分不开，改为多粒度判断（任务 1.2）加轨迹中的过程指标（任务 1.4、2.1），模块任务从六项改为五项。

01全流程：变化检测在哪里出问题

步骤 1 · 输入T1 / T2 两期影像可附带类别文本或需求文本
→
步骤 2 · 检测变化检测器输出变化掩码 change mask
→
步骤 3 · 存在的问题
误检：报了变化，其实没变 漏检：真实变化没报出来 掩码边界质量差
引入 Agent 之后理解 → 搜索可疑区域 → 判断是否变化 → 定位区域 → 调度工具修改掩码 → 核验后采纳或回滚误检场景检查变化掩码之内的区域，漏检场景检查变化掩码之外的区域（见 02 节）

02Agent 需要的六种能力

按 Agent 工作的顺序排列。每项能力下面拆出子能力；“原有”是原方案的四项，“新增”是根据 OVCD-v0 补上的两项。卡片下方说明误检、漏检两个场景各用到哪些子能力。

能力 1原有 · 原“读图”

理解

  • 1.1 地物识别：两期影像中各区域是什么类别
  • 1.2 判定标准理解：从类别名、示例或自然语言中归纳“什么算变化、什么不算”
能力 2新增

搜索

  • 2.1 漏检搜索：在检测结果之外提出可疑区域，并排序
  • 2.2 待查排序：在检测结果之内，决定先查哪个区域

不单独设任务：用 MLLM 搜索就是粗粒度上的判断（任务 1.2 的图块级）；与判断无关的部分（先看哪里、看多少、何时停）用轨迹中的错误访问率衡量（任务 1.4、2.1）。

误检2.2 掩码之内先查哪个漏检2.1 掩码之外去哪里找
能力 3原有 · 细化

判断

  • 3.1 存在性：区域内有没有目标类别的变化
  • 3.2 取舍：这个区域整体该保留还是删除
  • 3.3 方向与类型：新增、消失或类型转换
误检判断检测结果之内的区域漏检判断检测结果之外的区域
能力 4原有 · 细化

定位

  • 4.1 整目标：给出点或框，让工具分出整个目标
  • 4.2 局部：标出目标外多出的部分
  • 4.3 时相选择：在 T1 还是 T2 上分割
误检4.2 删除多余局部漏检4.1 补回整个目标
能力 5原有 · 细化

工具调度

  • 5.1 选工具：SAM 框提示、SAM3 类别裁剪、分数过滤，或不动
  • 5.2 给提示和参数：点、框、门限
  • 5.3 预算与停止：去误检和补漏各分多少调用，何时停
能力 6新增

核验

  • 6.1 结果核验：工具输出先检查，不对就回滚
  • 6.2 工具可靠性：判断工具在这张图上靠不靠得住
误检场景

检查变化掩码之内的区域：报出来的变化里，哪些不是真变化、哪些部分多出来了。

2.2 待查排序 → 3.2 取舍 → 4.2 删除多余局部 → 5.1 选工具（如 SAM3 类别裁剪） → 6.1 结果核验

漏检场景

检查变化掩码之外的区域：哪些真变化没有报出来。

2.1 漏检搜索 → 3.1 存在性 → 4.1 补回整个目标、4.3 时相选择 → 5.2 给提示 → 6.1 结果核验

在 OVCD-v0 中（LEVIR-CD building，三种免训练初始化：DynamicEarth 的 M-C-I、I-M-C，以及 ReA-OVCD），按像素算误检是错误的大头：误检像素占全部错误的 68–80%，其中 69–87% 是贴在已检出目标外面的多余像素。按目标算，整目标漏检率（14–51%）不低于整目标误检率（6–39%）。在 SECOND 上、用监督检测器时（实验 1），漏检反而是主要问题。所以两个场景都要做，误检场景更依赖“局部删除”（4.2）和工具；v0 初始化后要按来源重新统计。

04OVCD-v0 十一轮带给任务设置的结论

OVCD-v0 在 LEVIR-CD building 上跑了 11 轮，零样本 MLLM 在这个任务上已经做够。下面六条是它对任务设置的结论，第 02 节的六项能力就是据此调整的。详细过程见 doc/ovcd_v0_11rounds.html。

结论 1

初始化越强，MLLM 作用越小

MLLM 核实带来的增益：M-C-I 上 +2.1，I-M-C 上 +1.7，ReA-OVCD 上只有 +0.1。

判断任务应放在初始化弱、数据难的地方，或没有现成初始化的查询上。LEVIR 建筑已经饱和。

结论 2

不调用 MLLM 的工具贡献最大

SAM3 类别裁剪在 I-M-C 上 +6.2，在 ReA-OVCD 上加分数过滤 +1.3。

工具调度是能力体系的中心，动作空间必须包含这些工具。

结论 3

工具要逐图核验

裁剪的开关现在由验证集统一决定。SAM3 漏检的图上，裁剪会删掉真变化。

由此新增能力 6“核验”和任务 1.5。

结论 4

瓶颈常在“去哪里看”

候选池覆盖充足，截断到前 20 个后大部分漏检丢失。

由此新增能力 2“搜索”；它在轨迹里用错误访问率衡量，不单独设任务。

结论 5

判断能力取决于候选

同一个 Qwen，在不同来源的候选上 AUC 从 0.74 到 0.94 不等。

任务 1.2 要固定候选定义，并分来源报告。

结论 6

每个任务都要有“不用 MLLM”的对照

只在验证集上把 ReA-OVCD 的阈值调到 0.75，测试集 85.94，与完整 Agent 相同。

没有这个对照，会把调阈值的收益算到 Agent 头上。

07第一大类：模块任务

按 Agent 的工作顺序排列：理解 → 判断 → 定位 → 工具调度 → 核验，共五项。搜索不单独设任务，原因见任务 1.2 和 1.4。数据都来自第 06 节的数据集 v0 和示例集。

任务 1.1 · 理解

遥感图像理解

基于 v0-sem
设想
给定类别集合，让 MLLM 输出两期对象的类别。
目的
检验 MLLM 能否认出影像里的地物，以及文本对应的类别。
数据
v0-sem：从 SECOND 抽图（先按验证 64 / 测试 128），与 v0 按图分开。
区域怎么来
直接从 SECOND 的两期标签图切，不经过检测器：
① 每个像素在 T1、T2 标签图中各有一个类别，组成类别对 (T1 类, T2 类)；六类为低植被、无植被地表、树、水体、建筑、运动场，标签 0（未变化）跳过。
② 在类别对图上取 8 连通域，一个连通域就是一个区域，自带 T1、T2 两个真值类别。
③ 去掉面积小于门限（512² 图中先取 256 像素）和被图像边缘截断过多的区域。
④ 按 T1 类、T2 类分层抽样，每类设上限，避免低植被、无植被地表等大类主导准确率。
给 MLLM 看
与 1.2 相同：以外接框为中心外扩一倍裁成近景，两期都画出区域轮廓；分别问 T1、T2 中这个区域是六类中的哪一类。
评测
每期分类准确率、每类召回、两期都答对的比例。
局限
SECOND 只在变化区域标注两期类别，未变化区域两期都是 0、没有类别（凭记忆，需在服务器上核对：(label1 == 0) == (label2 == 0) 是否对所有像素成立）。所以 1.1 只考变化区域的类别；“没变化的地方是否真的没变”属于 1.2。相邻同类目标会连成一个区域，对认类别影响不大，先接受。
记录
沿用 v0-judge 的 JSON 格式，另加 t1_class、t2_class。

评审建议v0 里只有 SECOND 来源的图有两期语义，LEVIR-CD、WHU-CD 只有变化掩码，所以 1.1 单独用 v0-sem，零标注。判定标准理解（子能力 1.2）留给端到端任务 2.3–2.6（示例、自然语言两种前置条件）检验。

任务 1.2 · 判断

变化判断：图块、区域两种粒度

先做
数据
building 变化，从 LEVIR-CD、WHU-CD、SECOND 中挑 192 张作为 v0：T1、T2、building 变化掩码，每张图记录新编号、原始编号和来源（见第 06 节）。之后需要再扩。
粒度
两级，误检、漏检两侧都问：
图块（如 256²）：这块里有没有误检、有没有没标出的变化；
区域：给定的这个区域是不是误检、是不是漏检。
图块级就是 MLLM 做“搜索”的方式，真值由 GT 和 M0 直接算出，只计面积超过最小门限的错误目标。
不设整图级：按像素算几乎每张图都有误检和漏检，答案几乎全是“有”，测不出区分能力。
标注
检出的真实变化漏检误检三种颜色，以 GT 为准。
审核页
抽几个典型例子，展示全景和近景。
区域定义
用 Agent 部署时实际能拿到的单位，不用 GT 的形状：
误检侧 M0 的每个 8 连通域，问“是不是真实的建筑变化、该不该保留”；与 GT 重叠的精度 < 0.5 记为误检，否则为正确（负样本）。附着误检在这个单位上分不出，交给 1.3 的局部删除。
漏检侧 M0 之外的候选：另外两种初始化检测到而 M0 没有的连通域、分块 SAM3 两期差异的连通域；候选有 ≥ 50% 落在漏检区内记为漏检，否则为否。
oracle：直接用 GT 切出的漏检区，只作上界，和真实候选的差距就是候选形状造成的损失。
给 MLLM 看
以外接框为中心外扩一倍裁成近景（边长至少 128），两期近景上都画出区域轮廓；图块级给整块两期图像和当前掩码轮廓。
评测
正类 = 错误（误检侧为误检，漏检侧为漏检）。按粒度（图块 / 区域）× 侧（误检 / 漏检）分别报：
判别力：用 P(yes) 算 AUC 和 AP，与正类比例对比；
决策：阈值在验证集上选，报精度、召回、F1；
面积加权（仅区域级）：每个条目按其像素数加权，再算 AP 和精度，反映判错大区域的代价；与“全判是 / 全判否”比较。
不在 1.2 里算“执行后 F1 变化”：执行时补上去的形状由定位决定（MLLM 给点或框再交给 SAM），与被判断的区域不一定是同一个形状，所以 F1 收益放到 1.3 定位和端到端任务里评。
都按初始化、来源数据集、候选来源分开报；漏检侧另报 oracle 与真实候选的差距。
搜索相关的指标（错误访问率等）不在这里，见任务 1.4。

任务 1.3 · 定位

给出点或框，让 SAM 分出目标

基于 v0
设定
已知一个方块里有错（漏检或误检），让 MLLM 把它分准。隔离“产生候选”的影响：只测定位，不测判断。
数据
单独构造 v0-loc（从 v0 派生，不依赖 v0-judge 的候选）：
① 每个 GT 错误目标（v0 的真值区域）作为一个锚点，取以它为正中心的方块，边长 = max(外接框长边 × 2.5, 128)。
② 统计方块内的错误目标数，误检、漏检分开记（n_fp、n_fn），按总数分层：1 个、2–3 个、≥ 4 个。
③ 构造时不偏移。使用时再施加随机偏移，固定随机种子保证可复现；偏移上限 = (边长 − 锚点外接框边长) / 2，保证锚点仍完整在方块内。
④ 偏移后方块内的错误数可能变化，评测脚本按偏移后的方块重新计数，结果按实际错误数报。
MLLM 只看到方块和两期影像，看不到完美形状；方块里有多个错误时要求全部处理，按方块内全部错误像素评分。相邻锚点的方块可能重叠，统计时按锚点去重。

可能与 1.3 合并
