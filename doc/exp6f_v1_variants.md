# 任务：实验 6f，V1 验证器的诊断与变体

给服务器上的 Claude。前置结果见 `results/exp6a_pool.md`、`results/exp6b_verifier.md`、`interim/exp6/tables_6b_6e.md`。本任务沿用 6b 的代码（`code/probe/exp6b_*.py`）、训练池、验证集划分和评估口径，**不影响正在训练的 V2**，GPU 紧张时 V2 优先。

## 为什么做
6b 的 V1 结果有三个问题，本实验逐个诊断，并试几个便宜的修法：
1. **验证集为正、测试集为负**：怀疑是训练池（交叉拟合检测器）和测试池（官方权重）的检测器概率刻度不同（候选切块概率中位数 0.004 vs 0.037），验证集选的阈值到测试集偏松。
2. **加图像特征反而更差**：骨干版第 1–7 轮就到验证集最好，怀疑模型在"认场景、背答案"（有效样本只有约 2,671 张图），同时整图特征格子（8–16 px）比切块（中位 298 px，约 17×17）粗，看不清切块本身。
3. **每个切块单独判断**：没有用到邻近切块、多来源一致、与检测器预测区域的距离等上下文信号。

## 规则
- 所有取舍（特征、超参、阈值、早停）只看验证集（297 张）。测试集只在每个变体最终确定后评估一次。
- 不重训检测器；不用测试集数据训练或调参；不用真值语义图生成候选或特征。
- 单个变体如果预计超过 12 GPU 小时，先停下报告。

## 6f-A：概率刻度对齐（先做，最便宜）
在 none 版本上做，效果好再套到 6b 最好的骨干版本上。
1. **A1 图内排名**：把检测器概率的四个统计量（均值、最大、最小、90% 分位）换成该切块在**本图所有补漏切块**中的百分位排名（0–1）。其余特征不变，重训。
2. **A2 每图预算**：不改模型，只改并入规则。不用分数绝对阈值，改为每张图按分数从高到低并入，直到并入像素达到"该图检测器预测变化像素的 k%"，k 在验证集上选。对 none 和最好的骨干版本都做。
3. **A3 诊断（可选，A1/A2 不能解释时再做）**：用三个交叉拟合检测器在 test 上推理并取平均概率，重建 test 候选池中依赖检测器的部分（G0.05 和概率特征），用 6b 的 none 模型和验证集阈值评估。这只是诊断分布偏移，被改进的检测器变成了交叉拟合平均版，不作为主结果。
- 判断：A1 或 A2 后，测试集 ΔF1 的符号是否和验证集一致。

## 6f-D：上下文特征 + 树模型（便宜）
在 none 的元数据基础上加上下文特征，A1 有效就同时用 A1 的排名特征：
- 覆盖该切块的候选来源**个数**（多来源一致性），以及各来源是否覆盖（多热编码，替代现在的独热）；
- 到最近的检测器预测区域（0.5 掩码）的距离，是否与之相邻；
- 切块所属原始候选的面积、被切成了几块、同一候选内其他切块的检测器概率均值；
- SLIC 邻接切块中属于候选的比例、邻接切块的检测器概率均值；
- 图像级：该图检测器预测变化像素占比、该图候选切块数。

模型两种都训：6b 的 MLP，以及 sklearn 的 `HistGradientBoostingClassifier`（表格特征上通常更强，不需要新装包）。报告各特征组的消融（去掉某组后验证 AUC 的变化）和树模型的特征重要性。

## 6f-B：限制图像特征
在 none（或 D 中最好的表格模型）分数基础上，看图像特征能否带来增益：
1. **B1 残差修正**：logit = 冻结的基线 logit + 小 MLP(图像特征)，小 MLP 最后一层初始化为 0，加强权重衰减和 dropout。理论上不应差于基线。
2. **B2 降维**：图像特征只保留 |f1−f2| 和余弦相似度，用训练集拟合的 PCA 降到 16–32 维，再与元数据拼接训练。
- 骨干：6b 中验证 AP 最好的一个即可（6b 为 dinov3）。

## 6f-C：原分辨率小网络
绕开"整图特征格子太粗"的问题：
- 输入：以切块为中心裁 64×64（大切块按外接框外扩后缩放到 64×64），通道为 t1 RGB、t2 RGB、切块掩码、检测器概率图（A1 有效则用图内归一化后的概率图），共 8 通道。
- 模型：小的孪生或早融合 CNN（例如 ResNet18 宽度减半，从头训，或 ImageNet 初始化后改输入层），两期做一致的随机翻转、旋转和颜色扰动。
- 训练：用全部训练池，或按图像分层下采样（写明规模）；按验证 AP 早停。
- 先估算耗时，超过 12 GPU 小时就先报告。

## 评估（每个变体都做，同 6b 口径）
1. 验证集与测试集：AUC、AP、召回 80% / 90% 时的误检率、召回 80% 时补入像素精度，与 F1/2 门槛对照（验证 35.7%，测试 37.08%）。
2. 端到端：验证集选阈值（或 A2 的 k），测试集评估一次，报告 F1、P、R、ΔF1、新增 TP / FP 像素、目标级召回（按面积分桶），来源组合同 6b（B+G0.05、+H1、全部）。
3. **召回优先口径**（新增）：画"新增 FP 像素占检测器预测像素比例"与"目标级召回"的曲线，并报告新增 FP 预算为 5%、10%、20% 时的目标级召回。对照：6b 各版本、切块级 oracle。

## 判断问题（写进 summary）
1. 验证集为正、测试集为负，是否由检测器概率刻度不同造成？A1/A2 能否让两者符号一致？
2. 上下文特征或树模型能否把 AUC 提到 0.874 以上，并让召回 80% 时的像素精度明显接近 37%？
3. 图像特征在受限（B）或原分辨率（C）条件下，能否在表格基线上带来增益？
4. 所有变体中测试集 ΔF1 最好是多少？在召回优先口径下，固定 FP 预算时目标级召回能提高多少？
