# N9 工程执行规范：T3 标准数据集清洗重构 + `find_missed` 分任务独立标定与评测

> **最高执行准则（必读）**
> 1. **标准任务合法性原则**：T3 视觉示例检索的核心目标是“根据示例找出待测图中的同类目标变化”，待测图中必须真实存在待检索目标。此前混入的大量“扣除示例后 GT=0”样本属于待修复的数据构造问题。本轮必须先完成数据审计与重构，**禁止**继续在含大量空目标的旧 `dev60` 上反复优化空集拒识门控。保留原数据及历史结果用于追溯；“clean”是本轮新任务口径，不能将其得分与旧版未清洗任务得分直接当作同分布提升。
> 2. **任务解耦评测原则**：在论文体系中，`C0 (any)`、`C1 (build)`、`C1 (demolish)` 属于不同任务行。本轮**严禁**再将 LEVIR 与 SECOND 新建/拆除合并计算跨数据集 `pooled F1` 作为调参目标或晋级红线，必须按任务类型独立标定超参数，按数据集与任务行分别报告确认集及在线 Agent 的结果。
> 3. **API 预算授权**：预批复 **¥30 RMB 以内** 的 VLM 核验与在线 Agent 运行预算，新样本与新候选缺缓存时必须正常发起真实 API 调用。优先保证方法与真实实验执行，不花费过多精力做细粒度成本优化。
> 4. **执行边界**：本文件是下一轮工程执行任务书，**本次仅提交文档，不启动 N9 实验**。未经用户人工批准的新任务数据继续维持待审核；旧 GT、测试/报告划分和 N7/N8 历史指标原样保留。T3 新版数据应先生成独立审核材料并交由用户检查，不能因自动 QC 通过就视为已人工批准。

## 任务一：T3 任务数据审计、清洗重构与纯净版评测

### Step 1.1：审计并构建纯净版 `T3.1-clean` 与 `T3.3-clean`

对 SECOND 开发池与报告池的全部候选转换任务执行严格几何质量筛选（区分开发划分 `dev_tune` / `dev_confirm` 与独立报告集 `report`，严禁跨划分混用图像）。先核验各划分的既有来源、样本数和 GT 定义，严禁通过查看报告池指标选参。

1. **示例质量过滤（适用于 T3.1 与 T3.3）**
   - 示例连通域面积满足 \(64 \le |E| \le 4096\) 原生像素；
   - 剔除严重孔洞/破碎环状示例：设 \(E_{\mathrm{filled}}\) 为填充内部孔洞后的掩码，要求孔洞占比 \(\frac{|E_{\mathrm{filled}}\setminus E|}{|E_{\mathrm{filled}}|} \le 0.10\)，且边界框填充率或紧凑度正常，避免孔洞内异类地物误导视觉指代。紧凑度/填充率的具体计算和接受口径必须记录，不得按 confirm/report 评分事后调整。

2. **待测真值非空保证**
   - **T3.1（同图示例）**：扣除示例掩码 \(E\) 后，剩余同转换类型的真值掩码 \(GT_{\mathrm{rem}}=GT\setminus E\) 总像素数必须 \(\ge64\)，且至少包含 1 个面积 \(\ge32\) 像素的独立连通组件；
   - **T3.3（跨图双时相示例）**：待测查询图中的目标转换真值 \(GT\) 总像素数必须 \(\ge64\)，且至少包含 1 个面积 \(\ge32\) 像素的连通组件。

3. **归档要求**
   - 输出清洗前后的任务数量、通过/剔除数量和原因、涉及的转换类别分布表，保留旧任务 ID 到新任务 ID 的对应关系；
   - 将原本“剩余 GT 为空”的任务单独移入 `t3_empty_abstention_diag.json` 封存（本轮不测）；
   - 生成标准评测清单 `t3_1_clean_{tune,confirm,report}.json` 与 `t3_3_clean_{tune,confirm,report}.json`；若原始候选不足，明确列出实际数量与不足原因，不虚构样本或跨划分补足。

### Step 1.1-R：T3 旧/新任务示例人工审查页（用户新增要求，必须交付）

**这一页是“任务数据审查”，不是 Agent 轨迹回放**。为用户人工判断示例掩码是否合理、示例究竟指向何种变化，以及查询图是否确实存在可检索目标，单独创建中文审核页；**不要放到 `results/agent_baseline/demo_g3/` 或其它回放页面内**。

- 从**旧版 T3 任务**抽取 **3 例**，从**重构后 T3-clean** 抽取 **3 例**，合计 **6 例**。优先覆盖不同变化类别及 T3.1/T3.3 场景；避免只挑明显成功或最漂亮的样本。对新版示例应优先使用通过自动筛选的真实样本，并注明审核前仍为候选数据。
- 页面全部使用**中文描述和中文审核字段**。每例至少呈现：旧/新版本、T3.1 或 T3.3、样本/影像标识、示例的 T1/T2 原图、示例掩码叠加图、查询 T1/T2 图、查询真值变化掩码（审核专用，不得作为 Agent 推理输入）、目标变化类型、示例面积与孔洞占比、查询中剩余目标像素与连通组件，以及这例被保留/淘汰的原因。
- **重点让用户看“示例找得是否合理”**：示例是否确实落在目标变化区域、是否存在孔洞内其它地物、是否只截取建筑群的一小部分、是否是细碎/模糊区域；对同图 T3.1 还要直观看到示例扣除后可检索的剩余目标，对跨图 T3.3 展示示例图与查询图的对应关系。
- 6 例提供清晰的审核编号和逐例意见记录方式，至少支持“合理 / 不合理 / 存疑”及中文备注；默认均为**待人工审核**，不得自动标记通过。若页面仅用于查看而不支持在线保存审核意见，应显式说明并同时提供可填写的审核记录文件。
- 审核页和六例审查材料置于**独立的数据审核目录**（建议 `results/agent_baseline/n9_t3_data_review/`），提供独立 `index.html` 和审核清单，不改现有回放页。需同时提供页面访问/本地服务方法与原始图像、标注来源。
- 自动 QC 与这 6 例展示不等于用户已经批准整个 clean 数据集；本轮对“新版标准任务数据”的人工验收以用户后续明确反馈为准。

### Step 1.2：卸除过度拒识门控，评测去自匹配检索与在线 Agent

在纯净版 `T3.1-clean`（及 `T3.3-clean` 开发子集）上，移除 N8 中误杀非空召回的图内相对显著性空集门控与硬路由，完成以下三组干净对比：

1. **Baseline-Fixed**：原固定 `R1 Top8`（不去自匹配）；
2. **N9-Fixed（去自匹配特征检索）**：在 T3.1 中硬剔除与示例重叠率 \(r_{\mathrm{overlap}}\ge0.15\) 或 \(\operatorname{IoU}\ge0.15\) 的候选（微小交集取 \(C\setminus E\)），在 `dev_tune` 上对比 `delta` 与 `joint` 特征在 `Top5` / `Top8`（及可选温和双图核验）下的表现，选定最优配置后于 `dev_confirm` 冻结验证；
3. **N9-Agent（在线智能体）**：将去自匹配后的 `match_exemplar` 接入在线 Agent（同步开放 `view`、`SegEarth` 辅助转换查询与基础掩码编辑工具，恢复正常检索导向 Prompt，删除“鼓励空提交”提示词），在 `T3.1-clean` 确认子集（不少于 20 个任务 × 3 seeds）上对比 `Baseline-Fixed`、`N9-Fixed` 与 `N9-Agent` 的像素 F1、Precision 与 Recall。

**数据使用闸门**：优先完成 Step 1.1 与 1.1-R，提交审核页供用户检查。对尚未人工认可的新版 clean 任务，只能进行构造 QC 和明确标记的探索性开发检查；正式 N9 确认/在线任务评测须待用户明确批准。若确认集不足20条，应如实报告并等待数据决定，不跨划分凑数。报告集不用于方法选择。

## 任务二：`find_missed` 按任务轨道独立标定门限与分项评测

将主动补漏工具拆分为三个互不干扰的合法任务配置档（Profile）：`profile="any"`、`profile="build"`、`profile="demolish"`，根据当前任务自然语言约束自动加载对应档位参数，不依据数据集名称切换推理配置。同一 Profile 可在多个数据集上独立报告效果，不能通过合并跨集 pooled F1 决定晋级。

### Step 2.1：三轨道独立调参（严禁跨轨道共享阈值）

统一保留初始掩码 3 像素膨胀扣除（移除小于25像素残片），但在各自独立的 `tune` 集上单独选定候选源组合、语义概率差门限 \(\tau_{\mathrm{sem}}\)、核验器配置（`V0` / `V2` / `V4` 等）与送审上限 \(K\)：

1. **轨道 A：`any`（常规无方向建筑变化，在 LEVIR tune 与 WHU any tune 上评估）**
   - 目标：在高起点基线下严控 FP，争取净 \(\Delta\mathrm{F1}\ge0\)；
   - 允许极高门限（强语义变化差 + 高 DINO 残差触发 + 保守核验 `V2` + 小 \(K\le3\)）；若高饱和场景无候选越过门限，工具自然返回零新增，保护原高分掩码。
2. **轨道 B：`build`（新建方向约束，在 SECOND build tune 与 WHU build tune 上评估）**
   - 开放 `S1 + S2 + S3 + S4 + S5(dino_020)`；
   - 单独扫描有向建筑概率增长门限 \(\tau_{\mathrm{sem}}^{\mathrm{build}}\)、排序权重与核验器（比较 `V0` / `V3` / `V4`），最大化新建任务净 \(\Delta\mathrm{F1}\)。
3. **轨道 C：`demolish`（拆除方向约束，在 SECOND demolish tune 与 WHU demolish tune 上评估）**
   - **硬性关闭 S3、S4**，只启用 `S1 + S2 + S5(dino_020)`；
   - 单独扫描宽松的有向建筑概率下降门限 \(\tau_{\mathrm{sem}}^{\mathrm{demolish}}\)（包括 \(\tau=0\) 对照），比较 `V0`、`V4` 在 \(K=10/15\) 下的表现，检验先前全局门限造成的拆除召回损失。

上述轨道各自冻结配置。若同一轨道在 LEVIR/WHU/SECOND 存在差异，可以报告分数据集稳定性与失败案例，但不得在在线推理时读取数据集名选择门限。

### Step 2.2：各轨道独立 Confirm 验收与在线 Agent 验证

1. 冻结三个 Profile 各自最优超参，分别在 **LEVIR confirm**、**WHU（any/build/demolish）confirm**、**SECOND build confirm**、**SECOND demolish confirm** 上独立计算并列报：`初始基线 F1`、`补漏后 F1`、`净 ΔF1`、`新增 TP/FP` 与任务级胜负平统计。**禁止汇总跨数据集 pooled F1**，也不要以宏观单值替代各任务行结果。
2. 对离线 Confirm 得到正向净收益（\(\Delta\mathrm{F1}>0\)）的任务轨道，将分轨版 `find_missed` 接入真实在线 Agent，运行配对实验：每轨道不少于 **10 个任务 × 2 臂（无 `find_missed` vs 含分轨 `find_missed`）× 3 seeds**，独立汇报在线净提升。若各数据集确认结果不一致，需按明确受测任务行分别说明是否晋级及原因，不能用其他数据集收益抵消退化。
