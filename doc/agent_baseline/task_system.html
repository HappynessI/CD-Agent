总览

树状图是横轴的任务场景，蓝色是当前第一版 baseline 要做的任务。纵轴是附加约束，可与任一场景交叉：C0 无约束、C1 变化、C2 空间、C3 排除、C4 组合。交叉示例见「交叉示例：五种约束 × 五个任务场景」一节。

B

横轴一级：五类任务场景

场景 用户的处境 考察的 Agent 能力
T1 常见类别 能说出类别名，基础模型也认识 工具调用与结果合并
T2 稀缺类别 能说出名字，基础模型不认识 自主获取外部知识：查地图、检索参考图
T3 视觉示例 说不出名字，只能指给 Agent 看 从示例中学习，跨图匹配
T4 描述定义 只能描述特征、用途或目的 推理与任务分解
T5 已有结果更新 已有一份结果，需要改对或更新 发现错误、迭代修正与交互

一级按「Agent 靠什么认出目标」划分。每个一级有自己的二级标准。二级之间的区别都体现为工具链不同。

C

横轴二级：17 个任务

T1 常见类别｜按目标集合大小

二级 典型指令 工具链差异
T1.1 单一类别 “建筑” 调用一次基础模型
T1.2 多个类别 “建筑和道路” 逐类调用后合并，处理类别之间的重叠
T1.3 全部变化 “图中所有变化” 类无关提议，再过滤季节与光照造成的伪变化

T2 稀缺类别｜按参照从哪获取

二级 典型指令 工具链差异
T2.1 地图可查 “体育馆”“学校” 查 OSM 要素位置，在影像上定位后判断变化
T2.2 地图不可查 “光伏板”“养殖池” 检索参考图像构造示例；检索不到时把术语转写成外观描述

T3 视觉示例｜按示例代表什么

二级 典型指令 工具链差异
T3.1 图内点选 在图上点一个变化 从点选区域提取特征，全图匹配
T3.2 外部目标示例 另一张图里的一个目标 跨图匹配目标，再判断是否变化
T3.3 变化对示例 一对前后图块，如农田变大棚 匹配变化模式
T3.4 正负示例 “要彩钢棚，不要普通平顶房” 正例找候选，负例剔除相似项

T4 描述定义｜按需要哪种推理

二级 典型指令 工具链差异
T4.1 属性描述 “蓝色屋顶的厂房”“大型建筑” 先找大类，再按外观或尺寸筛选
T4.2 功能描述 “公共服务设施”“空置厂房” 用常识或 OSM 判断用途，外观不够
T4.3 目的驱动 “可能影响通行的变化”“违建排查” 先推断相关类别，再拆成 T1 或 T2
T4.4 关系描述 “沿新修道路两侧新增的建筑” 检测参照物，再做缓冲或包含判断并取交集

T5 已有结果更新｜按已有结果与反馈

二级 典型指令 工具链差异
T5.1 自主修正 “把这张结果改对” Agent 自己找错、改错、判断何时停
T5.2 点框反馈 用户在漏检处点一下 只改被指出的地方
T5.3 语言反馈 “左上角漏了一栋” 先理解反馈所指的位置和对象，再修正
T5.4 地图更新 一张旧地图加一张新影像 没有前时相影像，对照地图要素找出不一致处；参考 LaVIDE 的地图—影像变化检测
  • 清晰指令大致对应 T1、T2、T4.1。复杂或模糊指令对应 T4.2、T4.3。
  • T2.2 会把自己找到的参照当作示例，与 T3 共用匹配工具。区别在示例由 Agent 找，T3 的示例由用户给。
  • T4.3 最能体现规划能力。它要把一个目的拆成具体的检测子任务。
  • T4.4 与 C2 的区别在参照物从哪来。C2 的范围在看图前就已确定：用户画框，或查 OSM 取坐标。T4.4 的参照物要 Agent 从影像里检测出来，参照物本身可能就是新出现的。
D

纵轴：五种约束

约束与目标无关，任何目标都可以配任何约束。

约束 含义 例子 工具链增加的步骤
C0 无约束 该目标的变化全都要 “建筑变化” 无
C1 变化约束 限定变化方向、转换或程度 “新建”“拆除”“严重损毁” 在 T1、T2 上分别判断目标有无，确定方向；程度要逐个目标判定等级
C2 空间约束 限定区域 框、点，或“学校周边” 框点直接裁剪；地名描述先查 OSM 定位
C3 排除约束 去掉指定的一类变化 “除道路以外的变化” 先找出要排除的对象，再从结果中减去
C4 组合约束 以上多种叠加 “学校周边新建的建筑” 依次执行各约束并取交集

输入标签与应用领域映射

输入标签不立成第三条轴，只在讲得通的场景上启用。

标签 含义 适用场景 示例 数据要求
影像—影像（默认） 前后两期都是影像 全部 — 现有数据集
地图—影像 前时相是地图，后时相是影像 T1、T2、T4 “旧地图上哪些建筑被拆了” 影像带地理坐标，可与 OSM 对齐
异源输入 两期影像的传感器、模态或分辨率不同 T1、T2、T4 “灾前光学、灾后 SAR，找出倒塌的建筑” 已配准的多源影像对；Agent 按模态选工具或先做对齐
大幅影像 城市级大图，而非 256 或 512 像素切片 全部 “全市新增的温室有多少” 大幅影像及真值；Agent 需规划切块、筛候选区、汇总

T3 靠外观匹配，地图没有外观，因此不适用。T5.4 本身就是地图版本。地图在本体系中还充当 T2.1 的参照来源和 C2 的定位工具。异源输入时，SAM 3 这类光学工具在 SAR 上可能失效，选工具本身就是 Agent 要做的决策。当前第一版 baseline 只用影像—影像。

Agent 的输出

所有任务都输出变化掩码。数量、面积与文字说明按需输出。

输出 说明
变化掩码 所有任务的基本输出
数量与面积 由掩码计算，按需输出

掩码优化属于工作流内部的步骤，用来发现漏检与误检并迭代修正，本身不产生单独的输出。

H

分类原则与借鉴

  1. 一级按「Agent 靠什么认出目标」划分：工具已认识、自己查参照、用户给参照、推理得出。这种划分与输入模态无关，边界不重叠。
  2. 二级只在工作流不同时才拆：两个子任务用同一条工具链就能完成，不单独列出。
  3. 输出形式属于功能，不属于场景：掩码、数量、描述每个任务都能输出，因此不入轴。
借鉴对象 做法 用在哪里
VHM 按问的是什么分任务，不按文本题、图片题区分 原则 1
DORA 每类对应一个业务环节，写清考察的能力 每个二级的「工具链差异」
GTA、m&m's 等工具 Agent 基准 按需要的工具链区分任务 原则 2
RefCOCO 与 ReasonSeg 显式指代与隐含推理分开 T4 的二级
AnyChange 自动模式与点查询模式 T1.3 与 T3.1
交互式分割 点击反馈迭代修正 T5.2
