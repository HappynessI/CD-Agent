变化检测 Agent 任务设置：任务场景 × 附加约束

2026-11-03 · 针对 Ethan 与 GPT 讨论稿（四类分析维度＋综合报告、现象×操作矩阵）

横轴是任务场景，分两级；纵轴是需求附加了什么约束。二级划分只有一条标准：所需工具链是否不同。第一版先做 T1.1 单一常见类别 × 无约束（LEVIR-CD 建筑）和 T5.1 自主修正。

1. 总览

树状图是我们的任务场景（横轴），蓝色是第一版要做的任务。底部的纵轴约束和任一二级场景交叉，就是一个具体任务；交叉示例见第 3 节。

2. 横轴：任务场景设置

五类场景对应用户的五种处境。处境不同，Agent 要用到的能力也不同；输出都是变化掩码，差别在中间的过程。

场景用户的处境考察的 Agent 能力
T1 常见类别能说出类别名，基础模型也认识工具调用与结果合并
T2 稀缺类别能说出名字，但基础模型不认识自主获取外部知识：查地图、检索参考图
T3 视觉示例说不出名字，只能指给 Agent 看从示例中学习，并跨图匹配
T4 描述定义只能描述特征、用途或目的推理与任务分解
T5 已有结果更新已有一份结果，需要改对或更新发现错误、迭代修正与交互

一级按“Agent 靠什么认出目标”分；每个一级各有自己的二级标准，二级之间的区别都体现为工具链不同。

T1.2 多个类别“建筑和道路”逐类调用后合并，处理类别之间的重叠
T1.3 全部变化“图中所有变化”类无关提议，再过滤季节、光照等伪变化
T2 稀缺类别参照从哪里获取T2.1 地图可查“体育馆”“学校”查 OSM 要素位置，在影像上定位后判断变化

T5.2 点框反馈用户在漏检处点一下只改被指出的地方
T5.3 语言反馈“左上角漏了一栋”先理解反馈所指的位置和对象，再修正

  • 清晰指令大致对应 T1、T2、T4.1，复杂或模糊指令对应 T4.2、T4.3。

  • T2.2 内部会把自己找到的参照当作示例，和 T3 共用匹配工具；区别在于示例是 Agent 找的，不是用户给的。

  • T4.3 是最能体现 Agent 规划能力的一类：它要把一个目的拆成若干个具体的检测子任务。

  • T4.4 与 C2 空间约束的区别：C2 的范围在看图之前就已确定（用户画的框，或查 OSM 得到的坐标）；T4.4 的参照物要 Agent 从影像里检测出来，而且参照物本身可能就是新出现的，比如新修的道路。

3. 纵轴：附加约束

约束和目标无关，任何目标都可以配任何约束。

约束含义例子工具链增加的步骤
C0 无约束该目标的变化全都要“建筑变化”无
C1 变化约束限定变化方向、转换或程度“新建的”“拆除的”“耕地变建筑”“严重损毁的”分别在 T1、T2 上判断目标有无，确定方向；程度要逐个目标判定损毁等级
C2 空间约束限定区域框、点，或“学校周边”框点直接裁剪；地名描述要先查 OSM 定位
C3 排除约束去掉指定的一类变化“除道路以外的变化”“排除季节性植被变化”先找出要排除的对象，再从结果中减去
C4 组合约束以上多种叠加“学校周边新建的建筑”依次执行各约束并取交集

4. 分类原则与借鉴

分类遵守三条原则：

  1. 一级按“Agent 靠什么认出目标”分：工具已认识、自己查参照、用户给参照、推理得出。这样分和输入模态无关，边界不会重叠。

  2. 二级只在工作流不同时才拆：两个子任务如果用同一条工具链就能完成，就不单独列。

  3. 输出形式是功能，不是场景：掩码、数量、描述每个任务都能出，不入轴。

借鉴对象做法用在哪里
VHM按问的是什么分任务，不按文本题、图片题原则 1
DORA每类对应一个业务环节，写清考察的能力每个二级都写了“所需工具链”
GTA、m&m's 等工具 Agent 基准按需要的工具链区分任务原则 2

5. Agent 的功能与工具

功能是每个任务都要具备的能力，不单列为任务场景。

功能说明
输出变化掩码所有任务的基本输出
掩码优化工作流内置的核心算法：发现漏检和误检并迭代修正
数量与面积由掩码计算，按需输出
文字说明说明找到了什么变化、依据是什么，按需输出
工具用途
SAM 3按类别或提示在 T1、T2 上分割目标，是主要的基础模型
OSM 查询按影像范围和要素类型（如体育馆、学校、温室）取矢量和标签，支撑 T2 稀缺类别和用地名描述的空间约束
裁剪与缩放取局部区域给多模态大模型或 SAM 3 细看
掩码运算布尔运算、连通域、按面积或位置过滤
多模态大模型判断对候选区域判断是否变化、是否符合需求

OSM 查询需要影像带地理坐标。LEVIR-CD 和 SECOND 的切片是否保留坐标还要确认，自建 benchmark 时应记录每张图的坐标。

6. 已有结果更新：特色任务

掩码修正有两个位置：在 T1–T4 里它是工作流内置的核心算法；作为 T5 类任务时，用户直接给一张掩码。按会议结论，修正对象定为 SAM 3 的输出，不再逐个对比所有检测器。

工具开放规则：在目标数据集上全监督训练过的检测器（如 LEVIR-CD 上 F1 约 92 的 SChanger）不放进工具库，否则调用一次就拿到答案。
