总览

B

横轴一级：五类任务场景

场景 用户的处境 考察的 Agent 能力
T1 常见类别 能说出类别名，基础模型也认识 工具调用与结果合并
T2 基于 OSM 的变化检测 目标由社会功能、专有用地或设施语义定义（学校、体育场馆、公共设施），外观上难以与普通地物区分 调用与前时相时间对齐的 OSM 工具取历史矢量先验，锁定候选范围，再协同分割与核验
T3 视觉示例 说不出名字，只能指给 Agent 看 从示例中学习，跨图匹配
T4 描述定义 只能描述特征、用途或目的 推理与任务分解
T5 掩码优化 已有一份结果，需要改对或更新 发现错误、迭代修正与交互

一级按「Agent 靠什么认出目标」划分。每个一级有自己的二级标准。二级之间的区别都体现为工具链不同。

C

横轴二级：13 个任务

T1 常见类别｜按目标集合大小

T1：用户在指令中显式指定一个或多个基础模型可识别的地物类别，Agent 根据指定类别完成变化检测。

任务 任务名称 典型指令 核心能力 标注
T1.1 单类别变化检测 “找出建筑的变化” 单目标类别的检测和验证
T1.2 多类别变化检测 “找出建筑和水体的变化” 多目标检测、工具组织和结果合并

T2 基于 OSM 的变化检测｜不拆分子任务

T2：目标由社会功能、专有用地或特定设施语义定义（如学校、体育场馆、公共设施），仅凭正射影像外观难以与普通地物区分。Agent 需调用与前时相时间对齐的 OpenStreetMap 工具检索历史矢量要素，作为外部空间与语义先验锁定候选范围，再协同双时相分割与核验工具提取真实变化掩码。

原先的 T2.1 地图可查、T2.2 地图不可查合并为这一条，本版不拆分子任务。

T3 视觉示例｜按示例代表什么

二级 典型指令 工具链差异 标注
T3.1 图内点选 在单时相图上点一个变化（点/框/mask） 从点选区域提取特征，全图匹配
T3.2 外部目标示例 另一张图里的一个目标 跨图匹配目标，再判断是否变化 暂时决定不做
T3.3 变化对示例 一对前后图块，如裸地变建筑 匹配特定的‘变化模式/转换关系’（涉及方向）
T3.4 正负示例 “要彩钢棚，不要普通平顶房” 正例找候选，负例剔除相似项 暂时决定不做

T4 描述定义｜按需要哪种推理

T4：用户没有直接给出可供基础检测器识别的目标类别，而是通过属性、功能、关系或状态描述目标，Agent 需要将描述解析为可执行的视觉操作并完成检测。

二级 典型指令 工具链差异 标注
T4.1 属性描述 “蓝色屋顶的厂房”“大型建筑” 先找大类，再按外观或尺寸筛选 暂定为面积和颜色，building 颜色数据正在从 SECOND 中进行标注
T4.2 功能描述 “公共服务设施”“空置厂房” 用常识或 OSM 判断用途，外观不够 与 T2 任务合并
T4.3 事件影响分析 识别洪水发生后被淹没的道路、受到洪水影响的建筑 事件解析 → 对象识别 → 状态证据获取 → 状态关联判断 需要有建筑功能标注，需要数据
T4.4 空间关系查询 “沿新修道路两侧新增的建筑” 检测参照物，再做缓冲或包含判断并取交集 参考 CV 中指代表达分割，使用句子级指代描述

T5 掩码优化｜按已有结果与反馈

二级 典型指令 工具链差异
T5.1 自主修正 “把这张结果改对” Agent 自己找错、改错、判断何时停
T5.2 点框反馈 用户在漏检处点一下 只改被指出的地方
T5.3 语言反馈（句子级指代描述） “左上角漏了一栋” 先理解反馈所指的位置和对象，再修正
T5.4 地图更新 一张旧地图加一张新影像 没有前时相影像，对照地图要素找出不一致处；参考 LaVIDE 的地图—影像变化检测
  • 清晰指令大致对应 T1、T2、T4.1。复杂或模糊指令对应 T4.2、T4.3。
  • T4.3 最能体现事件推理。它要先解析事件，再定位对象、取状态证据，最后做状态关联判断。
  • T4.4 与 C2 的区别在参照物从哪来。C2 的范围在看图前就已确定：用户画框，或查 OSM 取坐标。T4.4 的参照物要 Agent 从影像里检测出来，参照物本身可能就是新出现的。
D

纵轴：五种约束

约束与目标无关，任何目标都可以配任何约束。

约束 含义 例子 工具链增加的步骤
C0 无约束 该目标的变化全都要 “建筑变化” 无
C1 变化约束 限定变化方向、转换或程度 “新建”“拆除”“严重损毁” 在 T1、T2 上分别判断目标有无，确定方向；程度要逐个目标判定等级
C2 空间约束 限定区域 框、点，或“学校周边” 框点直接裁剪；地名描述先查 OSM 定位
C3 排除约束 去掉指定的一类变化 “除道路以外的变化” 先找出要排除的对象，再从结果中减去
C4 组合约束 以上多种叠加 “学校周边新建的建筑” 依次执行各约束并取交集

输入标签不立成第三条轴，只在讲得通的场景上启用。

标签 含义 适用场景 示例 数据要求
影像—影像（默认） 前后两期都是影像 全部 — 现有数据集

H

分类原则与借鉴

  1. 一级按「Agent 靠什么认出目标」划分：工具已认识、自己查参照、用户给参照、推理得出。这种划分与输入模态无关，边界不重叠。
  2. 二级只在工作流不同时才拆：两个子任务用同一条工具链就能完成，不单独列出。
  3. 输出形式属于功能，不属于场景：掩码、数量、描述每个任务都能输出，因此不入轴。
借鉴对象 做法 用在哪里
VHM 按问的是什么分任务，不按文本题、图片题区分 原则 1
DORA 每类对应一个业务环节，写清考察的能力 每个二级的「工具链差异」
GTA、m&m's 等工具 Agent 基准 按需要的工具链区分任务 原则 2
RefCOCO 与 ReasonSeg 显式指代与隐含推理分开 T4 的二级
AnyChange 自动模式与点查询模式 T1.3 与 T3.1
交互式分割 点击反馈迭代修正 T5.2
