# 核心任务数据重构与 HTML 视觉抽样审核规范（T5.2/5.3、T4.4、T3）

> **最高执行准则（必读）**
>
> 1. **阶段边界（仅离线建库 + 静态 HTML 抽样送审）**：本轮唯一目标是按全新物理与任务边界重构 **T5.2/T5.3、T4.4、T3** 候选样本池，并各抽取代表性样本生成静态自包含 HTML 审核页供研究者肉眼把关。**本轮严禁提交任何在线多轮 Agent 推理作业，保持零（或极低）API 消耗。**
> 2. **区分“离线建库筛选”与“在线推理输入”**：
>    - 在**离线构造基准数据阶段**，允许使用 `GT` 真值掩码、`DINOv2` 特征相似度、`SegEarth` 语义概率图及弱基线预测 `M_init` 筛选高质量样本、填充实例孔洞、验证同质性与非平凡性；不得以“不能接触真值或特征”为由跳过筛选条件。
>    - 生成最终任务 JSON 时，仅向后续 Agent 暴露各任务合法的测试输入，**严禁在 Agent 推理输入中泄露 GT**。离线筛选指标和 GT 只能用于建库、审核与评测。
> 3. **物理实例完整性红线**：所有任务一律以**完整独立地物连通域（实例）**为最小保留或剔除单元（需先做孔洞填充净化），**严禁**使用九宫格硬裁剪切碎完整建筑掩码，**严禁**保留带大面积内部孔洞的畸形掩码。
> 4. **人工审核闸门**：本轮输出是候选数据与审核材料，不等于任务数据正式批准。审核前保持 `pending_review`；生成 HTML 和汇总后停止，待用户审查，不开展正式评测、在线 Agent 或批量发布。

**仓库和分支**：`ethan-404-sys/CD-Agent`，`claude/project-thread-2tuaib`。本规范是专项数据重构与审核任务书；`doc/agent_baseline/README_ai.md` 继续维护长期技术历史。原有 N7/N8/N9 结果、旧数据和历史评测不得覆盖或删除。

## 模块一：T5.2 & T5.3 掩码优化（WHU-CD & SECOND 同源配对镜像）

### 1.1 任务定位与数据源要求

- **“外 B 内 B+C”定位**：对外输入统一为 `(T1, T2, M_init, Feedback)`，标准输出为更新后的**最终二值变化掩码**（方案 B）；但选定的待优化区块必须覆盖新建漏检（需看 `T2`）、拆除漏检（`T2` 是空地，需回 `T1` 找边界）与显著误检/粘连修边，促使后续 Agent 内部采用 B+C 协同求解。
- **放弃 LEVIR，迁移至大尺度数据集**：全部在 **WHU-CD** 与 **SECOND**（分 `build` 新建与 `demolish` 拆除）上构造。
- **真实弱初始化 `M_init`（零合成扰动）**：**严禁**对 `GT` 做人工腐蚀、膨胀或挖洞；**必须**采用仓库内较差/粗粒度的真实预测结果作为 `M_init`（如早期 `ovcd_v0` 粗预测、未加核验的固定方向弱基线、高阈值欠检版单轮 `SAM3` 跨期差分或 `SegEarth` 粗概率差掩码），筛选整图初始 F1 处于 **20%～75%**（非饱和）的图像。

### 1.2 单目标显著病灶筛选与双模态镜像生成

每条任务仅选定 **1 个肉眼清晰的大中型错误连通域** \(R^*\)（SECOND 面积 **≥400 像素**，WHU-CD 面积 **≥800 像素**），覆盖三类病灶：`FN-Build`（大中型新建漏检）、`FN-Demolish`（大中型拆除漏检）、`FP / Coarse-Merge`（大片裸地/阴影误检或粗边界粘连）。

对**同一个目标区块 \(R^*\)** 同步生成配对题目（T5.3 内部不再拆分子类）：

- **T5.2（点/框反馈）**：输出指向 \(R^*\) 的提示点或 `bbox` 坐标及操作意图（补检 / 剔除 / 修边）。
- **T5.3（自然语言反馈）**：输出指向同一 \(R^*\) 的单句自然质检指令，固定句式为 **`[粗略方位/邻近显著地物] + [目标对象] + [漏检补全 / 误检剔除 / 粘连修边]`**。示例：
  - “画面右上方紧邻道路的那栋大型厂房漏检了，请补全。”
  - “画面中部原有的厂房在后期已拆除，当前掩码漏检了该建筑，请参照前期影像补全。”
- **抽样送审数量**：**WHU-CD 抽 3 条 + SECOND 抽 3 条**，覆盖上述三类病灶，每张审核卡片同时展示配对的 T5.2 与 T5.3。

### 1.3 数据边界与可核查性

弱初始化必须标记具体生成方法，真实预测与 GT 分开存储；任务输入中只能出现 `M_init`，不能把局部理想 GT 当作提示。区块修复后的“理论 F1”仅供**离线审核诊断**，不作为 Agent 输入。WHU-CD 官方 GT 口径与历史“两期自行做差”问题分开处理；T5 审核页**不沿用与其不相干的 `Old GT overlay`**。

## 模块二：T4.4 空间关系查询（`T4.4 × C0` 纯净边界重构）

### 2.1 严格正交的任务边界（剥离 T4.1 与 C1）

为确保与 `T4.1`（颜色/面积属性）及 `C1`（新建/拆除方向）严格正交，本任务指令**严禁**出现屋顶颜色、面积大小词汇，也**严禁**限定新建、拆除或前后态类别转换。

- **标准句式公式**：**`找出 + [影像可检测的显著参照地物] + [无歧义拓扑空间关系] + 的[基础类别]变化`**。
- **合法指令示例**：
  - “找出沿主干道两侧的建筑变化。”
  - “找出紧邻水体周边的建筑变化。”
  - “找出运动场周边的建筑变化。”

### 2.2 四步干净构造流水线

1. **变化实例原子化与填洞**：将 WHU-CD 或 SECOND 的建筑变化真值拆分为连通实例，执行孔洞填充（孔洞率 \(=0\)），滤除 **<150 像素**碎斑。
2. **提取高显著参照地物（Anchor）**：在 SECOND 中提取两期稳定存在的大面积线性道路（硬化地表走廊）、水体或运动场；在 WHU-CD 中利用高置信 `SegEarth` 道路/水体掩码（或对齐的矢量要素）提取贯穿性主干道或水系。要求参照物在影像中肉眼一目了然且无多义性。
3. **无歧义拓扑判定与整实例保留**：优先采用俯视无歧义拓扑关系——**沿线两侧 / 紧邻周边**（对参照物做固定像素宽度缓冲区求交）；仅当线性地标近似水平或垂直贯穿全图时才允许使用**北侧（上侧）/ 南侧（下侧）/ 东侧（右侧）/ 西侧（左侧）**。凡与缓冲区相交达标的变化实例**整栋完整保留**，绝不沿缓冲区边缘切断建筑掩码。
4. **非平凡性硬过滤（防退化）**：入选图像中**必须同时存在**满足该空间关系的目标建筑变化实例（**≥1 栋，总面积 ≥400 像素**），以及不满足该空间关系的同类别干扰变化实例（**≥1 栋**），确保无脑输出全图建筑变化（T1.1）会产生明显误检。

- **抽样送审数量**：**精选 3 条**最具视觉代表性的样本送审。

## 模块三：T3 视觉示例（同质建筑实例簇重构，主攻 `T3.1`）

### 3.1 根治“示例与真值怪异”的源头约束

- **彻底剔除无定形地表类**：放弃 SECOND 中的裸地、低矮植被、树木等无固定形状转换，**仅在 WHU-CD 建筑变化与 SECOND 建筑/运动场实例子集**上构造任务。
- **单栋规则示例过滤**：示例掩码 \(E\) 必须为单栋完整建筑/场馆实例，面积 **\(200 \le |E| \le 5000\)** 像素，内部孔洞率 **≤0.05**，最小外接矩形填充率（紧凑度）**≥0.45**（剔除多栋民房粘连成片的大街区或细长碎条）。

### 3.2 图内外观同质簇预筛（Homogeneous Cluster Sampling）

真实视觉示例任务要求“待检索真值在视觉外观上确实与示例属于同款目标”（如同一工业园区同批次新建的蓝顶厂房、成排同规格仓库或同款排屋）：

1. **单期视觉特征一致性**：在建筑存在的那一期影像上（新建看 `T2`，拆除看 `T1`），提取示例 \(E\) 与同图其余各变化实例 \(I_k\) 的单期 `DINOv2` 特征余弦相似度 \(\cos(f(E),f(I_k))\) 及屋顶 RGB 均值差。
2. **同质成簇与非空保证**：筛选同图内存在 **≥2 个其余变化实例**（即连同示例共 **≥3 个同款实例**）与示例满足 **\(\cos \ge 0.75\)** 且屋顶主色调一致的样本，且扣除示例后剩余目标真值总面积 **\(|GT_{\mathrm{rem}}|\ge400\)** 像素。优先挑选图内全部（或 **≥85% 面积**）变化建筑均属于同一外观簇的干净园区/住宅区样本，确保真值与示例在肉眼上协调统一。
3. **双口径真值保存**：元数据同时记录 `gt_full`（含示例本身的完整同类变化集合，用于自然可视化展示）与 `gt_rem`（扣除示例后的净剩余目标，用于净召回评测）。

- **抽样送审数量**：**精选 3 条** `T3.1` 同图同质簇样本送审；若顺带构造跨图同质对 `T3.3`，可额外附 3 条，核心必审仍是 `T3.1` 3 条。

## 四、统一静态 HTML 视觉审核页规范（核心交付物）

生成静态自包含审核目录 **`results/agent_baseline/task_reconstruct_audit/`**，入口为 `index.html`，所有配图存放在相对路径 `assets/*.png` 下，确保目录打包下载到本地后直接打开，无裂图或外部依赖。

页面顶部设置清晰导航栏/分节：

- **Tab 1：T5.2 & T5.3 掩码优化（WHU 3 + SECOND 3）**
- **Tab 2：T4.4 空间关系查询（3 条）**
- **Tab 3：T3 视觉示例（3 条）**

核心必审样本共 **12 张卡片**（T5 配对 6 张、T4.4 3 张、T3 3 张）；如额外生成 T3.3 样本，另作附加区，不替代必审数量。所有描述、字段、提示语和审核备注均使用中文。

### 4.1 T5.2 & T5.3 审核卡片布局

- **第一行（全图 4 列）**：`T1 原图（带目标区块虚线框）` | `T2 原图（带同一虚线框）` | `弱初始化 M_init（蓝）+ 选定待优化区块高亮框及 T5.2 点/框标记（黄/红）` | `GT 对照图（区分已对区域、该区块理想真值、误检区域）`。
- **第二行（局部 1.8× 放大 4 列）**：针对选定区块并排展示 `局部 T1` | `局部 T2` | `局部 M_init + 点/框` | `局部 GT`。
- **底部信息栏**：数据集与图 ID、变化方向、弱初始化方法名、病灶类型与像素面积、初始全图 F1 vs 修复该区块后理论 F1、配对的 **T5.2 坐标参数**与 **T5.3 自然语言指令**。

### 4.2 T4.4 审核卡片布局

- **全图 4 列**：`T1 原图` | `T2 原图` | `提取的参照地物掩码（青色）+ 空间拓扑缓冲区范围叠加图` | `实例级真值划分图（命中的目标变化实例涂亮绿色，同图被排除的干扰变化实例涂暗灰色/橙色，直观验证未切碎建筑且非平凡）`。
- **底部信息栏**：数据集与图 ID、参照物类别与空间关系类型、命中实例数/像素数 vs 排除干扰实例数/像素数、生成的 **`T4.4 × C0` 纯净指令文本**。

### 4.3 T3 审核卡片布局

- **第一行（全图 4 列）**：`T1 原图（标出示例框）` | `T2 原图（标出示例框）` | `示例掩码单独高亮图（青色）` | `完整同质真值图（示例涂青色，待检索其余同款目标涂亮绿色，直观检验无挖空违和感）`。
- **第二行（局部同质性放大比对）**：并排展示 `示例 E 的 T1/T2 局部放大图` 与 `图内其余 2 个目标实例的 T1/T2 局部放大图`。
- **底部信息栏**：数据集与图 ID、转换方向、示例面积与孔洞率、剩余目标实例个数与总面积、各目标与示例的 **单期 DINOv2 余弦相似度及 RGB 均值差**。

### 4.4 审核使用约束

GT 叠加、理论 F1、DINO 相似度及人工筛选理由属于**审核专用信息**；不得泄露进未来 Agent 的标准输入。卡片应明确标识“待审核”，允许研究者逐例判断“合理 / 不合理 / 存疑”并填写意见；无法持久化时，另提供可编辑的审核记录文件。
