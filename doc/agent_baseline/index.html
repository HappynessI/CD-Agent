语义

修改 · 结束

add_region · remove_region refine_regionSAM 重分一个连通域 submit

不放进主设定

SChanger 等全监督检测器在 LEVIR 上训练过，调一次就 92 分，任务就没了。可作为“专家工具”另设一档
M-C-I 这条路 segment_everything→ extract_features→ compare_features→ classify→ threshold
I-M-C 这条路（SAM3 版） segment_text ×2→ match_instances
Agent 可能走的 segment_text ×2→ match_instances→ view→ ask→ remove_region→ refine_region→ submit

DynamicEarth 的两种方法都只是这些工具的一条固定路线。Agent 能不能重新找到它们、能不能混着用、修改类工具能带来多少，就是“接管工作流”可以量化的地方。工具实现基本都在 code/ovcd_v0/ 里，M-C-I 的提议和分数也已缓存。

07+优化外循环：跑通之后持续调到足够好

提示里只允许写通用的方法性指导，不能写数据集名或针对 LEVIR 的规则。这一步是工程调优，相当于把人工调提示交给 Claude 来做，论文里如实写「经过 N 轮验证集迭代」，不作为方法贡献。

不用向 Ethan 确认就能做
  • 换工具、加工具：SimpleClick、AnyChange、RemoteCLIP、APE、Grounding DINO 等
  • 自主下载权重和代码、配环境
  • 改架构或转换方向：CodeAgent 当主线、加反思步骤、推翻现有设计
  • API 和 GPU 按需用，费用只报告
结果可信的底线，不能碰
  • 不用在 LEVIR 上训练过的模型，也不在 LEVIR 上训练
  • 真值、数据集名、针对 LEVIR 的规则不进 Agent 输入
  • 测试集只在冻结配置时评，评完不回头改
  • 新工具先登记来源、许可、训练数据和单项指标

另外持续维护一份 LEVIR 分析：什么在限制 F1（工具上界、决策错误、停止错误各占多少），每类错误在各轮里怎么变化，哪些工具换了有效、为什么。

07++变化检测专用 harness 与 skill（Ethan 11-04）

相对 DynamicEarth 的固定组合，Agent 高出 10 到 27 分，但大部分来自换成 SAM3 这个更强的基础模型。真正属于 Agent 调度的，是同一套工具下「固定路线 → Agent」这一段：T1.1 约 +0.6，T5.1 约 +2.0（相对给定掩码）。harness 和 skill 的目标就是把这一段做大。

harness 能力做法现状
skill系统提示只放 skill 索引，Agent 按需 load_skill 读全文。首批：核验、掩码修正、修边界、找漏检、提交前自查待做
规划plan 工具：开局写待办清单，过程中更新，复核时对照待做
状态摘要每轮附当前掩码、已核验和未核验数、剩余预算、清单进度部分有
上下文管理留图策略已有；补上把旧工具结果压成摘要部分有
提交前复核r7有
换任务、换数据集只改配置不改代码：T1.1、T5.1，以后 T1.2、T2.x待做

skill 只能写通用的变化检测方法，不写数据集名或 LEVIR 特有的规则。它等同于人写的提示，属于 harness，论文里要做「去掉 skill」的消融。
